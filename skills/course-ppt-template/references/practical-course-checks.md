# 实操课程的内容复核

从课程表拆出目标、关键概念、课堂操作、学员交付与验收方法，逐项对照，不把后续课程的能力提前宣称为已实现。

## 界面与交互课

- 每个状态写明主动作、返回目标和重新开始路径。起始页没有上一页时，不要同时写“所有页面都返回上一页”。
- 课表要求按键流转时，必须把原型事件与动作对应起来。按钮、键盘模拟和真实设备按键是不同验证范围；没有设备/API证据时，不编造实体事件名或“硬件只能如何操作”的规范。
- 原型的演示数据应明确标注，不把可点击界面写成真实识别或计算已经接通。
- 工具实践要给清晰输入和迭代动作：哪一屏、发现什么问题、希望如何改变。

## 通讯与服务课

- 用一次具体请求和响应讲方法、路径、请求体、状态码与响应体。示例接口明确为课程约定，不能冒充平台官方API。
- POST 的通用含义不是“必然新建资源”；可以说“本课用 POST 上传并创建任务”。
- 区分请求已受理、查询成功与任务完成。202 不证明业务完成，200 查询响应也不自动表示任务已完成。超时只表示本次等待超时，不能直接断言服务端处理失败。
- 实操页不能只列“实现上传、实现查询、配置网络”。应给可执行的操作链：生成或取得最小示例、按README安装与启动、确认地址和端口、检查目标设备可达性及HTTPS证书、上传取得ID、查询并记录回执。
- 没有源资料支持时，不编造已经可用的示例仓库、启动命令或线上环境。可给完整工具输入，让其同时生成最小服务及启动说明，再要求学员按实际产物操作。
- 将输入要求与本课产物区分。若本课要搭服务，已有HTTPS地址不能无说明地成为先决条件；本次测试不部署的限制也不应混入面向学员的教学页。

概念解释正确、操作可跟随、边界明确之后，再检查画面。PPT检查通过不等于原型运行或服务器联调已经通过。
