# 将定稿转为 Rokid 论坛富文本

Rokid 论坛写文章通常使用富文本编辑器，不能假设把 Markdown 源码直接粘贴进去就能得到标题、代码块和图片。Markdown 路线适用于图片已由Rokid 论坛原生上传，并用 `finalize_images.py` 回填完地址之后的稿件。未回填稿中的占位符不可发布。普通 TXT 则使用下方专门的纯文本路线，不经过 Markdown 解释。

## 离线生成

该脚本的 Markdown 路线需要 `markdown-it-py 3.0.0`，普通 TXT 路线只需 Python 3.9+ 标准库；其他前处理脚本的依赖见各自说明。Markdown 路线选择允许安装依赖的环境，建议独立虚拟环境，不修改用户全局环境：

```bash
python3 -m venv /绝对路径/新的虚拟环境
/绝对路径/新的虚拟环境/bin/python -m pip install -r requirements-render.txt
/绝对路径/新的虚拟环境/bin/python scripts/render_richtext.py \
  --article /绝对路径/finalized.md \
  --output /绝对路径/新的富文本输出目录 \
  --allow-host verified-upload-host.example
```

示例主机不是实际上传地址。含图稿须换成从本次 Rokid 原生上传观察、并已加载核实的精确小写主机；与 `finalize_images.py` 的参数保持一致，可重复传入多个主机。没有图片时省略 `--allow-host`，预览的 `img-src` 为 `'none'`。

安装依赖需要访问包源；转换脚本本身不联网、不打开浏览器、不上传文件、不执行正文或代码。输出目录必须新建或为空，输入、输出及已有父路径不能是符号链接。macOS 临时目录使用真实路径 `/private/tmp`。源文件不会被改写，已有输出不会被覆盖。

### 普通 TXT：保留原文字面与空白

```bash
python3 scripts/render_richtext.py \
  --literal-txt /绝对路径/原文章.txt \
  --output /绝对路径/新的纯文本输出目录
```

`--literal-txt` 与 `--article` 互斥，必须传原 TXT，不传已经转义的准备稿。默认严格 UTF-8，自动处理 UTF-8 BOM、UTF-16 BOM；确认是 GB18030 时加 `--encoding gb18030`。不猜测错误编码，不以替换字符继续。按准备脚本相同约定，把 CRLF/CR 规范为 LF 后建立文本基线。

纯文本整体放入一个语义 `<pre>` 块，不添加 `<code>` 子标签，也不指定编程语言。所有空格、制表符、起始和末尾空行保留；HTML 的首个 `<pre>` 换行规则已在生成时补偿，不靠预览 CSS 维持空白，也不把 ASCII 空格替换为 NBSP。`#`、反引号、看似图片或链接的字符、HTML 和注释全是原文字面，不会执行、上传或被解析成排版。

清单使用 `source_format: txt`、原字节 `source_sha256`、编码和 `literal_text_sha256` 等基线，不伪装成 Markdown。此路线没有实际图片与超链接；若用户确认 TXT 实际采用 Markdown 语法，才走 `prepare_text.py --txt-as-markdown`、图片回填和 `--article` 路线。Rokid 论坛可能清理或改变 `<pre>`；粘贴后仍须核对空格、空行与字面文字，不能只凭本地预览宣称已保真。

生成三个文件：

- `article.fragment.html`：仅含文章语义 HTML，供支持 `text/html` 剪贴板的宿主工具使用。
- `preview.html`：简约的本地检查页，不声称与Rokid 论坛排版完全一致。无脚本；在浏览器打开时，图片标签可能向已上传的Rokid 论坛 CDN 请求图片。
- `manifest.json`：原稿及输出哈希、图片出现顺序与 alt、标题层级、代码内容与哈希、链接和列表起始编号基线。它含用户文章内容及图片完整签名链接，属于私有工作输出，不应一起分享技能包。

脚本输出 `ready_for_reviewed_ui_transfer_not_published` 只表示已生成待人工核对的本地 HTML，不代表已经粘贴、保存、发表或通过审核。

## 保真与限制

基于 CommonMark，另开启 Markdown 表格和删除线。保留原文标题层级，包括正文首个一级标题；不推测删除“重复标题”，不新增图注或外层文章标题。在下方兼容范围内保留图片位置、alt、title、列表起始编号和引用结构。代码不执行、不格式化，按 CommonMark 的换行规范保留内容；CRLF 会规范化为 LF，围栏代码的末尾换行依标准解析规则处理。需逐字验证代码时，使用清单中的内容及哈希，并在 Rokid 论坛编辑器中再次核对。

### 独立图片段与论坛兼容

本技能保留的 Rokid 编辑器实测记录显示，`<p><img ...></p>` 曾被粘贴过滤，而顶层 `<img width="100%">` 成功。渲染器因此直接检查 Markdown 解析 token：只有顶层段落且其唯一内容是一张图时，才移除该段落容器并输出正文顶层图片。不是只改 CSS，也不对任意 HTML 做正则拆解；图片仍处于原来的阅读位置，原 alt / title 和独立图注保留。

兼容示例：

```markdown
## 原章节

原正文。

![原 alt](https://verified-upload-host.example/example-only.png "原 title")

图｜原图注
```

图片与正文 / 图注需要空行分段。正文混排、同段多图、强调或链接包图、列表、引用、表格中的图片会明确报错，且不会生成部分输出。脚本不把图片强行移到容器外，也不删除包图链接来凑成功；在经核对的副本中规范这些结构，或在原生编辑器逐块插入并核对原含义。普通不含图的列表、引用、表格照常保留。适配只是已知兼容方案，仍需对当前论坛编辑器先做小范围粘贴验证。

### 文字与地址检查

不运行扩展插件，不自动美化标点或链接。原始 HTML 被转义为可见文字而不是执行；预处理阶段已要求人工规范原始 HTML，不应靠这个步骤把它悄悄删除。例外是代码之外的 HTML 注释：它可能包含原本隐藏的内部备注，脚本会明确阻断，要求先在工作副本中人工检查、移除或改写，不能把注释变成公开正文。围栏代码、缩进代码和行内代码中的字面注释示例照常保留。检测时额外解析 HTML 语法只是为了辨认注释，不会渲染或执行 HTML。

相对链接、`file:`、活动协议、协议相对链接等明确阻断，需先在工作副本中人工改为合适的绝对地址或段内锚点。普通链接只接受 `http:`、`https:`、`mailto:` 和 `#锚点`。图片默认不放行任何主机；每张图片都必须来自本次实际 Rokid 论坛原生上传，按与 `finalize_images.py` 一致的精确小写 `--allow-host` 授权，可重复传多个。仅接受 HTTPS 及默认 HTTPS 端口；参数不得包含协议、路径、端口或通配符，也不会自动允许子域。预览页 CSP 只增加这些精确主机。不继承知乎、CSDN、掘金或云存储的整域白名单；这个参数不能用来放行未经上传的外链。脚本拒绝残留的 `RK_IMAGE`、其他平台图片占位，以及旧 Word `{{IMAGE_1}}` 占位，不把两套清单混用。

链接校验针对真正进入输出的链接和图片。图片已转为托管行内图后，原 Markdown 可能保留未再使用的本地引用定义；这种定义不产生链接或图片，不会因此误阻断。被正文实际引用的本地或危险地址仍会在生成 HTML 之前阻断。

解析选项依据 [markdown-it-py 官方使用说明](https://markdown-it-py.readthedocs.io/en/latest/using.html)：显式禁用 HTML 输出，仅按需开启表格和删除线规则。本技能的图片域名、注释阻断和转入验收要求属于工作流约束，不是Rokid 论坛官方 API 承诺。

不支持的公式、脚注、复杂扩展、富文本嵌入应在转入前发现，并与用户确认处理方式，不把“能解析”当作语义完整。文内 `#锚点` 地址保留，但Rokid 论坛是否生成对应锚点仍需实际验证。

## 通过原生编辑器转入

1. 先观察当前Rokid 论坛编辑器及工具能力，确认账号、稿件和目标编辑区。调用能力中明确提供 HTML 剪贴板时，把 `article.fragment.html` 作为 `text/html` 写入，再用原生粘贴；不要仅把 HTML 字符串当作纯文本粘贴。
2. 没有这种剪贴板能力，但工具支持打开本地文件和浏览器原生复制时，可以打开 `preview.html`，只选中 `<article>` 对应的正文区域进行原生复制，再粘贴到Rokid 论坛。不能把预览页顶端的提示条也贴进正文。选区和复制操作须使用当前工具已支持的浏览器/原生 API。
3. 两种方式都不可用时，观察Rokid 论坛当前是否真的提供 Markdown 导入入口；有则按该入口导入并验证。没有则通过原生编辑器逐块重建标题、列表、引用、代码、表格，并在原位置插入上传图片。若工具无法可靠完成，停在本地稿并说明缺失的能力，不能声称已发布。
4. 不使用页面 `evaluate` 修改 DOM、编辑器内部状态、私有接口、Cookie/Token 或臆造的上传 API 来替代可见编辑器操作。不要靠手工写 `innerHTML` 来“证明”页面保存成功。
5. 粘贴后滚动查看全部正文：核对标题数和层级、图片顺序及对应图注、代码空格与换行、表格结构、引用、列表编号和链接。Rokid 论坛可能清理 CSS 或改变 HTML 结构，语义结果才是验收依据。必要时用工具允许的只读 DOM 检查配合截图确认。
6. 发布授权、保存与审核状态判断，继续遵守技能主文件和浏览器验收说明。已经生成本地 HTML 或预览完整，不构成发布成功证据。

测试只使用合成素材：

```bash
/绝对路径/虚拟环境/bin/python -B -m unittest discover -s scripts -p 'test_render_richtext.py' -v
```

没有安装 Markdown 解析依赖时相应渲染测试会跳过。测试中的 HTML5 `<pre>` 首换行与字符保真检查另需可选测试依赖 `html5lib==1.1`；它不属于发布脚本运行依赖，也未装入分享包。未装时只跳过这两项 HTML5 检查，不能把“跳过”汇报成实际解析测试通过。
