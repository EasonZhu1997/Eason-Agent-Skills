# 布局与提示词模板

按当前任务选一个模板。花括号表示需要替换的内容，不应原样出现在成图里。用户已经给出准确文案时优先复用。

## 通用骨架

```text
制作一张中文粉笔板书教学图，主题是“{主题}”，让{读者}看完能够{学习结果}。
采用{比例，默认 16:9}，正面平视深灰黑板，轻微擦痕和粉笔颗粒。
主体为清楚的白色手写粉笔字，蓝色表示分区与指向，黄色突出重点，红色仅用于确有依据的风险或错误。
笔触自然但文字不能模糊，黑板纹理保持低对比。不要木框、教室背景、品牌 Logo、水印或无关口号。

布局：{各区的位置、大小层级和阅读顺序}。
上图文字如下，保持中文、数字、英文大小写准确，不额外编造标签：
{标题、副标题、各区标题、节点说明、必要箭头标签、底部结论}

关系：{逐条列出箭头起点、终点和含义；哪些事项只并列而不相连}。
插图：{少量与讲解有关的通用简笔图标；可省略人物}。
重点：{一句结论中的重点词；明确下划线、圈点或局部高亮}。
留足边距和区块间距；线不穿字，不裁掉任何内容。说明字需在常见阅读尺寸下读清。
{如有参考图：该图仅用于画风，不复制其中的主题、品牌、人物造型或页码。}
```

## A. 问题解释板书

适合“为什么会这样”“哪里容易出问题”。从参考图抽取的布局起点：顶部大标题；左侧场景列表；中间原因或机制示意；右侧影响；底部一句结论。

- 左区可配编号和小图标；它们表示分类而非操作步骤。
- 中区突出最关键的行为或机制，需要时加入一幅简笔场景。
- 右区若列出若干可能后果，应写“可能出现”，使用并列卡片；只有明确的因果过程才逐项连箭头。
- 底部把结论写具体，可补一两条行动建议。没有证据时不要标注效果提升比例、成本或耗时。

## B. 操作步骤板书

适合教学、使用教程和项目工作流。标题写要完成的事，主体为编号操作与必要检查点，底部为“做到什么算完成”。

可直接试用的例子：

```text
画一张 16:9 粉笔板书：“一次小改动，怎样提交给开源项目？”
副标题：“以修改一处 README 为例”。
黑灰板面，白色手写粉笔正文，蓝色分区和操作箭头，黄色突出完成标准。
上部主体分成“原项目”“你的 GitHub 副本”“本地电脑”三个区域。
主线文字依次为：
“1 读贡献指南｜先确认改什么”
“2 Fork｜在 GitHub 创建副本”
“3 Clone｜把自己的副本下载到电脑”
“4 Branch｜为这次修改建分支”
“5 修改与检查｜改一处 README 并检查预览”
“6 Commit｜保存本地提交”
“7 Push｜把分支推到自己的副本”
“8 Pull Request｜请求原项目评审”。
先后阅读按编号连续，并明确各步骤发生的位置。
Fork 从原项目指向自己的 GitHub 副本；Clone 从自己的副本指向电脑；
Branch、修改与检查、Commit 在本地；Push 从本地回到自己的副本；
Pull Request 从自己 GitHub 副本中的修改分支，指向原项目的目标分支，表示请求合并。不要把本地 Commit 画成已上传。
右下角小卡片：“维护者评审｜可能要求继续修改；通过后再合并”，从 PR 连接到此卡片。
若展示返工回路，明确返回本地“修改与检查”，再 Commit、Push 更新同一个 PR；空间不足可只保留评审说明。
底部黄色结论框：“完成标准：改动清楚、可检查，PR 中写明目的与验证结果”。
复杂路径分两行排版并明确连接，连线不穿过文字；不加入网站 Logo 或虚构按钮。
```

以上是 GitHub 协作概念例子，不是当前网站按钮位置截图。若用户要求具体界面操作，先观察对应页面并按实际流程修改。

## C. 概念对比板书

适合分清易混术语。以两三列展示相同维度，主体不要连成时间线。底部再用一个小场景或一句话总结差异。

```text
制作 16:9 中文粉笔板书，标题“Commit 和 Push：改动到了哪里？”
左栏：“Commit｜发生在本地｜记录一次修改｜还没有上传”。配电脑与记录本简笔图标。
右栏：“Push｜从本地到远端｜上传提交记录｜远端分支更新”。配两个位置和上传箭头。
两栏按“位置、动作、结果”对齐，边框蓝色，正文白色。
底部用黄色划线突出“先保存本地记录，再上传远端分支”。
一处红色提醒：“Push 不等于合并 PR”。
使用轻微粉笔颗粒和擦痕，文字清楚，不画成真实 GitHub 页面，不加入品牌标志。
```

## D. 系列课件

一张放不下且需要连贯讲解时，先给每页确定一个独立学习结果，例如：

1. 问题页：读者能识别容易失败的情形。
2. 方法页：读者能照着步骤完成一个小任务。
3. 示例页：读者能按检查点判断结果是否达标。

这只是拆页方式，不强制三张。实际只交付一张时不要加“01 / 03”。系列内一致使用颜色含义、专有名词和编号规则，每页避免依赖“如上图”才能理解。

## 定向修正

编辑目标已明确时，描述修改范围和保留范围，例如：

```text
编辑这张已有板书。只把右栏“Commmit”修正为“Commit”，保留其字号、位置和粉笔笔触。
其余文字、箭头、分区和配色保持不变。修改后完整保留画布边缘。
```

如果是关系错误，写出旧边需要删除、新边起终点以及相应标签，不只说“把流程画对”。
