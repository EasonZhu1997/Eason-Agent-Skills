# 知乎图文验收

## 准备基线

保留本次源文件 SHA-256、标题和正文副本。仅修图时以网页当前正文为基线，以用户指定 Word 的图文关系校正图片；正文和旧文件不一致时，不擅自回滚网页文字。

TXT 对照可见文字、连续空格、缩进及全部换行；默认预格式文本路线不将其解析成 Markdown。粘贴后平台若将预格式块改成普通段落导致空白折叠，需要恢复或说明未完成，不能只检查 HTML 源码中仍有空格。MD 对照标题、列表、代码、链接与图片位置；Word 对照实际页面，不能只信转换后的文本。未决修订、公式、文本框、复杂表格、隐藏或外链媒体要明确处理，不将提取不到当成原稿没有。

## 编辑器校对

- 标题框符合用户指定标题；正文第一行没有被擅自删掉。
- 主章和小节使用真实标题结构，粗体大小变化不能代替层级。平台整体将 h1 下移为 h2 时，检查相对层级和目录效果，不机械判为错误。
- 每一个图片出现位置对应原图，即使一张图出现两次也保留两处；图注紧邻对应图，没有多余重复图注、图片堆或占位符。
- 代码比较实际代码内容，包括每个换行、缩进、引号和特殊字符；工具栏语言标签、复制按钮及行号不计入代码。
- 段落、编号起点、列表嵌套、引用及表格列对应正确；被平台清理的结构用原生工具恢复，不能静默省略。
- 链接保留真实目标。知乎包装的跳转 URL 可以解析目标参数核对；链接变成卡片时，确认没有丢失锚文本所承担的说明。
- 话题、摘要、封面、来源及创作声明符合实际；不勾选无关商业或付费权益。

## 正式页校对

打开平台返回或实际作品列表提供的文章地址。核查保存、发布、审核中或仅作者可见等提示，不依据一次点击推断结果。

仅统计正文范围的图，排除头像、推荐和封面。对懒加载图片逐段滚动触发；工具允许读取 DOM 时，以 `complete && naturalWidth > 0` 辅助确认，再结合原图内容、媒体标识与相邻图注判断位置。工具没有 DOM 能力时用逐段视觉核验并说明范围。

明确区分已加载、加载失败和未触发加载。只看到部分图片就报告部分，不写全图正常。缩略图格式与原始 URL 可能不同，但图文对应仍必须逐项证明。

同一登录态下能看到文章不证明匿名访客都能看见；未经未登录核验，不声称公开可访问验证通过。平台发布成功也不代表通过征文审核或奖励已到账。

## 交付记录

只在当前任务目录记录：

```text
标题：<确认标题>
原稿 SHA-256：<本次原稿>
文章 / 草稿地址：<实际观察值>
状态：<本地完成 / 草稿保存 / 提交成功 / 审核中 / 正式页可见>
图片：<总出现数、已验证数、失败数、未验证数>
图注、层级、代码、链接：<实际检查结果>
未完成：<需用户处理的事项>
```

不要把账号、联系方式、Cookie、密钥、带签名的图片地址或真实素材放入分享包。任务达到用户要求后停止，不自动转发、投稿其它平台或重复更新。
