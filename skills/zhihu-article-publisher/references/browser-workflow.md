# 知乎浏览器操作与易错点

## 证据与适用范围

此前一次 Word 图文实操记录（2026-09-05）确认使用过知乎“导入 > 导入文档”导入 DOCX；图片获得平台托管，但部分标题、段落、代码及链接仍需按原稿恢复。本文将它作为历史操作经验，不承诺所有账号、浏览器或未来页面都有相同入口。

本分享包制作时只核查公开入口与本地记录，没有重新发布文章，也没有完成新一轮真实编辑器上传试验。公开的 [知乎专栏入口](https://zhuanlan.zhihu.com/) 可以帮助定位文章产品；具体编辑按钮须以运行时登录页面为准。

## 找到正确文章

从当前登录页面可见的“写文章”、创作入口或作品管理进入。先确认作者账号、内容类型及用户给出的目标；没有“写文章”时检查创作菜单，不能换成“写回答”凑数。

修改文章时从该文章的可见编辑入口进入，或打开用户明确给出的编辑地址。不要用某个历史文章 ID、新建草稿地址或隐藏 API 作为通用入口。打开页面失败不等于文章不存在；先确认标签是否失效、登录是否过期。

## Word 原生导入

1. 在获得本次上传授权后，观察编辑器“导入”菜单是否提供文档入口以及实际允许的格式。
2. 先保存当前目标文章和正文基线。仅在空的新稿，或确认可替换的目标正文上导入，防止覆盖用户后续手动修改。
3. 用宿主支持的文件选择器选择那一份明确的 DOCX；不要自动选整个文件夹、宏文件或其他附件。
4. 等待导入与图片转存完成，读取预览。已正确导入的图片无需重复上传；失败图按 Word 清单逐个替换。
5. 对照原稿恢复标题级别、代码、段落与超链接；粗体段落不等于真正标题，灰底文字不等于代码块。

若宿主提供 Playwright 风格文件选择器，遵照当前工具文档先等待 `filechooser`、点击本轮已定位按钮，再 `setFiles`。如果只提供原生文件对话框，就使用其文件选择流程；不要编造未提供的 API。

## TXT / Markdown 的富文本输入

Markdown 先完成图片清单、上传映射与离线 HTML 渲染。图片不能上传时保留阻断状态，不把占位符或外链直接发布。纯 TXT 使用 `--literal-txt` 路线直接生成预格式文本，不需要图片清单或回填；其空格和缩进在编辑器中也要保留，不能改成普通段落后宣称未变。

聚焦实际正文区后，使用宿主明确支持的 HTML 粘贴；例如工具文档确实提供 `paste(html, {format: "html"})` 时才用它。`format: "md"` 可能只粘贴 Markdown 源码，不保证渲染。没有 HTML 粘贴能力时，可从可访问的本地预览复制渲染内容，或用当前页面确实支持的 Markdown 导入；再不具备条件时逐块用原生标题、列表、代码工具重建。不能宣称纯文本粘贴已完成排版。

不通过 JavaScript 修改 `innerHTML`、调用隐藏编辑器模型、读取 Cookie 或请求私有上传/发布 API。正常粘贴也可能被编辑器清理格式：小批量试贴标题、链接、代码和图，再决定整稿或分节输入，避免为测试创建公开文章。

## 图片对应与图注

上传文件用内容哈希命名可减少同名混淆。上传结果只有明确保留文件名时，才能用 alt 当文件名。否则改为小批次或逐张上传，立即记录当前文件与平台返回的媒体地址。

临时图片区仅用于建立映射，正式稿中不能保留文首图片堆。用实际预览里的 `<img>` 或上传结果读取地址和媒体标识，完整 URL 在当前任务中保留，不输出到公开日志。单看尺寸、数量或异步顺序都不够。

平台如果同时保存缩略图和原图地址，要记录实际可观察到的关系；不要擅自修改后缀或删签名参数。先确认托管图片，再按原出现位置放入正文。原 alt 不自动生成额外可见图注；原稿已有图注必须紧邻对应图，避免重复。

## 发布与恢复

填写标题、当前必需的话题或其它信息，封面使用用户授权素材。是否原创、转载来源或包含 AI 辅助创作，按实际情况和当前规则填写，不为了发布而虚假声明。

发布前查看预览。只存草稿时等待明确保存状态，不点发布。发布后读取提示并访问实际文章页；看到审核中就记录审核中，不反复提交催审。

操作超时先查看原草稿、作品列表及实际文章，不因为按钮无响应就再建一篇。遇到验证码、登录或需要新授权时保存状态并交给用户。文章发布不包含自动报名、问卷、提现或申请奖金。
