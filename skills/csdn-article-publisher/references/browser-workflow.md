# 浏览器录入与上传

本文件整理可复用的操作经验，不是 CSDN 固定接口合同。页面和工具可能变化，应在每次使用时重新确认。无需为使用本技能访问原作者的电脑或文章。

## 工具前提

需要能读取页面、点击控件、定位编辑区、操作剪贴板/选区和上传本地文件的宿主浏览器能力。若没有，只能准备本地图文材料，不能假称完成网站上传。工具名称以当前环境为准。

优先连接用户指定的现有标签页。用户账号、登录凭据和 Cookie 不写入脚本或技能；让用户在目标网站自行登录也是正常流程。

## 编辑器识别

曾观察到 CSDN 富文本工具栏含“图像”“使用 MD 编辑器”，正文位于 iframe；另一类编辑器可能使用 Markdown 文本框。只把这些作为寻找入口的线索，不硬编码 iframe ID、标签页 ID 或坐标。

作用域限定在正文，别把 AI 助手侧栏、文章摘要、目录导航或标题输入框当成正文。先读取编辑区开头、结尾、字数及图片，再做写入。

需要导出正文时，可使用允许的只读 DOM 能力读取编辑区 HTML。不要读取浏览器 Cookie、令牌、隐藏状态、框架存储，也不要通过该能力修改页面。

用户明确要求同步掘金、知乎时，先读 [多平台同步](cross-platform-sync.md)。优先检查 CSDN 官方同步助手及当前浏览器条件；官方同步到目标草稿后再校对/按授权发布，不把这个入口误当作无须目标登录的一键公开发布。只检查入口不应勾选平台后触发真实同步。

## TXT / Markdown 的转入选择

- 普通 TXT 默认运行 `render_richtext.py --literal-txt`，传原 TXT，而不是 Markdown 转义后的中间稿。使用真正的富文本粘贴或可验证的原生预格式块，逐项检查缩进、连续空格、首尾空行及 `#`、反引号、图片写法的字面文字；不假设 Markdown 编辑器源码区能原样展示它们。
- MD / Markdown 先通过 `prepare_text.py` 清点图片、原生上传、`finalize_images.py` 原位回填。保留完整 Markdown 图片语法，不能把图片改成普通链接。
- 只有当前页面确实是 Markdown 编辑器，才将最终 Markdown 作为源码录入该区域，并查看渲染预览；不要把侧栏/摘要/富文本正文误当源码区。
- 富文本编辑器先运行 `render_richtext.py --article`，再用宿主明确支持的 `text/html` 剪贴板或在本地预览正文中的原生复制粘贴，详见 [richtext.md](richtext.md)。HTML 字符串本身不是富文本粘贴。
- 当前无可靠富文本能力时，仅在实际提供的入口中导入，或用原生控件逐块重建并验证；无法保真就停在本地稿说明限制，不通过隐藏编辑器状态或私有接口注入。

图片路径来源随输入变化：Word 看原图清单与图注；Markdown 看 `CS_IMAGE` 占位、原图 SHA-256 和相邻正文。不要用 Word 修复器去读取 Markdown 清单，也不要为了凑图数改变原文。

## 原生文件上传

1. 在正确插入点放置光标，打开当前图片上传控件。
2. 如果工具使用 filechooser 事件，先等待事件，再点击触发按钮，最后选择本地绝对路径。
3. 只有当前选择器确实支持多选，才传多个文件。页面声明的格式、大小限制优先。
4. 等待编辑器出现图片；记录网站实际生成的图片地址和加载尺寸。
5. 检查图像不是“图片转存失败”的替代图。替代图也可能有非零宽高。

部分当前工具提供 `waitForEvent('filechooser')`、`chooser.isMultiple()`、`chooser.setFiles(...)`；另一些使用原生文件选择窗口。读宿主文档选择其支持的方式，不照搬不存在的 API。

## 小批次富文本粘贴

可选路径：编辑器能把 `<img src="data:image/...;base64,...">` 自动上传到平台时，用小批次转存。首次尝试前备份原文，试一张并验证 URL，再继续。

本次复用经验：大型整篇内嵌 HTML 曾导致连接中断；约 2 MB 附近的批次也曾出现无变化。**这不是确认过的 CSDN 硬性上限。** 可从更小批次开始，以实测结果调整；大单图用文件选择器上传，不为绕限制擅自缩小或重绘原图。

粘贴后必须验证：该批实际出现了多少张、地址是否已经是正式平台地址、是否仍有内嵌数据/失败占位。批次成功不代表位置正确。

## 光标与整体替换

图片小部件被选中不等于正文光标已定位。粘贴可能替换当前图片，或者没有插入；只看工具“成功返回”不足以判断结果。

- 使用当前有效的编辑区和唯一正文锚点定位；必要时用前后文消除歧义。
- 原生可访问性编号必须根据最新树获取。修改内容后不要长期沿用旧编号。
- 每次写入后读取附近正文/图片，必要时目视确认。
- 整体替换前：已保存原正文备份、所有 URL 已齐全、本地输出通过审计；把焦点置于正文内部，再执行全选和富文本粘贴。
- 替换后立即检查正文首尾、图片总数、图注对应、标题未被覆盖、临时标记不存在。若有异常，不提交发布。

## 常见故障的处理

| 现象 | 检查与处理 |
| --- | --- |
| 图片在目录前堆叠 | 先收齐 URL，再依据 Word 图注逐图归位；不要继续向同一光标盲贴 |
| 图片加载了但显示转存失败 | 检查替代图、临时文件路径、实际图内容；从 Word 原文件重新上传 |
| 粘贴无变化 | 查弹窗、编辑区焦点、图像选区、剪贴板格式和批次大小；不要连续重复相同操作 |
| 图片仍是 data URI | 等转存并再看状态；若未转存，用本地文件上传，不能直接当已完成 |
| 发布超时 | 查当前成功提示及同一文章状态；禁止自动再建一篇 |
| 浏览器断连/工具超时 | 按当前宿主文档恢复连接；重新确认标签页和保存状态，不重放整段流程 |
| 系统锁屏/验证码 | 请求用户接手，不绕过；原发布状态和剩余项写到任务工作目录 |

长操作拆成可以检查的小段。不要用长时间阻塞等待掩盖未知状态，也不要在仍有任务可推进时只做重复轮询。
