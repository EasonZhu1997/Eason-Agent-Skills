# 保存与公开页面验证

## 提交前的必要证据

1. 原文：标题不变；开头、结尾、章节、代码换行和链接保留；没有误贴 HTML 源码或丢段。
2. 数量：正文图片出现次数等于经核对的源文清单，不把头像、封面设置、按钮图标或拖动占位当正文图片。
3. 对应：每张图片 URL 对应上传记录中的编号；尺寸可做初筛，不能仅凭同尺寸判断是同一图。疑似混用时目视比对原图。
4. 顺序：图片和其图注/上下文对应；没有图全部集中在目录前、末尾或另一个章节。
5. 加载：图像 `complete` 且 `naturalWidth > 0`，并排除“转存失败”替代图、WPS 临时路径、本地文件和未转存的内嵌数据。
6. 整洁：旧重复图、临时编号、测试粘贴内容已清除。窄屏/正文区域没有明显溢出、拉伸或超大空白。
7. 来源保真：TXT 核对字面符号、连续空格、制表符及首尾空行，不把示例代码或图片写法解释成排版；MD 核对标题层级、代码内容与换行、列表起始编号、引用、表格及链接。富文本粘贴后不能残留 Markdown/HTML 源码；Markdown 编辑器必须检查渲染预览，不只核对源码。
8. 清单匹配：Word / HTML 修复按 Word 数字编号及锚点；MD 按 `CS_IMAGE` 清单中的每次出现和源图指纹。不得残留未回填占位、把第三方图床或普通文章 URL 冒充原生上传图；图片总数相同不证明逐图相符。

在工具允许的只读 DOM 范围内可以导出图片 `src`、`alt`、加载尺寸和相邻段落文字，作为自动核对输入。还应目视抽查封面、密集信息图、截图、靠后章节，以及任何疑点。不要为了截图检查调用隐藏应用状态。

## 保存后的四个独立状态

| 状态 | 足够说明该状态的证据 | 不代表 |
| --- | --- | --- |
| 编辑器已核对 | 当前正文和图片清单通过检查 | 内容已保存 |
| 草稿已保存 | 网站明确保存提示或重新打开后内容一致 | 已提交审核 |
| 已提交审核 | 网站明确成功/审核中提示 | 已公开或审核通过 |
| 公开页已验证 | 打开目标公开文章，正文与图片位置正确、图片可加载 | 其他网站同步完成 |

不要点击“发布”后立刻宣称全流程完成。按用户要求提交后，确认当前文章的成功状态；再尝试打开公开页。如果仍审核中，报告已提交和未验证项即可，不无限等待、不重复发布。

若任务只要求草稿，完成草稿验证后停止，不为满足“公开页检查”而擅自发布。

## 可选同步的逐平台验收

执行了 [CSDN 官方同步路线](cross-platform-sync.md) 时，分别核对 CSDN、掘金、知乎，而不是共用一个状态。先确认每个指定目标生成的是正确账号下的对应草稿，再查正文、代码与逐图位置；已正确转存的图片不重复上传。只有目标平台实际完成发布和公开页核对，才能标记该站“公开页已验证”。

一站成功、一站失败或未知时分别交付，并先查同步历史及现有目标文章再恢复。不要因重试生成重复文章，不把“助手同步成功”写成“全平台已发布”。

## 面向用户的结果示例

“已修复 N 张原图，图注位置核对通过。更新已提交，网站显示审核中；公开页尚未验证。”

“已保存草稿，重新打开后正文与 N 张图均一致；没有点击发布。”

“电脑已锁屏。本次已完成 X，尚未完成 Y；请先解锁后继续。”

这些是表达边界的示例，不是可未经检查直接套用的结论。
