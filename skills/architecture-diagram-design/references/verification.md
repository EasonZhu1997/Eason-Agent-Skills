# 验收清单

## 先看关系

- 读者能否说出每层按什么分、各组件负责什么？有没有把产品目录错画成调用架构？
- 总览和运行图的层名、顺序、组件身份是否一致？步骤与组件是否清楚区分？
- 从起点按箭头能否依次走完业务？每条线是否对应内容契约，不多一条“装饰闭环”？
- 请求和返回是否可分辨？箭头有没有指向无关卡片或仅与目标擦边？
- 跨端/云/网关说明是否来自资料？开发工具是否被误放进实时主线？
- 待核实和假设有没有被图形掩盖为确定事实？

## 再看实际渲染

- SVG/其他源格式必须实际打开或渲染后检查，XML 合法不等于可读。
- 全图和缩至实际使用宽度都能读：中文无缺字，长卡名不溢出，细字不靠放大才能看见。
- 所有卡片、箭头和标签在画布范围内；文字不被线穿过、不被卡边遮住、不互相叠压。
- 颜色之外有编号或图例，背景低对比，橙色只用于本次主线。
- 图例、假设标记和“感谢 成都常顺鑫”在指定位置，低于正文层级但清晰可读。
- 修改后重新渲染；交付的源文件和预览应是同一版本。

## 可复用的行为试验

用本地、假设性资料检验，不调用真实账号或外部发布：

1. 给出设备、运行时、业务服务、文档四类资料，要求总览：不应凭空增加请求路径。
2. 在同样资料中描述采集—处理—反馈：复用同一分层，步骤按归属放置，只绘真实描述的边。
3. 资料没有说明处理在手机还是云端：标待核实或询问，不因参考图而替用户做部署决定。
4. 需求只有三层四步：应重排模板，不能保留无关的第四层与第五、第六步。
5. 用户只要求蓝墨手绘海报：不应把此现代矢量模板当作唯一合法输出。

本清单和包内示例不构成自动制图程序。技能结构校验、SVG 语法校验、实际图像检查和真实技术核验是不同的验收层级；只做过哪一层，就报告哪一层。
